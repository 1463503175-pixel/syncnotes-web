# 陈笃山的记事本软件化方案

目标：从当前网页形态升级为“Windows 桌面软件 + 手机 App + 同 Wi-Fi 自动同步”的本地优先记事本。

## 最终形态

- Windows 桌面版：像普通软件一样双击打开，数据默认保存在本机 `E:\SyncNotes\web\data`。
- 手机 App：手机本地也有自己的数据缓存，离线能查看和编辑。
- 同步方式：电脑和手机在同一个 Wi-Fi 下时，手机自动发现或手动连接电脑地址，同步记录和附件。
- 数据策略：本地优先，网络只用于同步，不依赖公网服务器。
- 远程访问：如果以后需要外网访问，再单独接入云同步或私有服务器，不和本地模式混在一起。

## 数据原则

- 记录继续使用 `E:\SyncNotes\web\data\notes.json`。
- 草稿继续使用 `E:\SyncNotes\web\data\drafts.json`。
- 附件继续使用 `E:\SyncNotes\web\attachments`。
- 同步新增 `E:\SyncNotes\web\data\sync-meta.json`，记录设备信息和同步状态。
- 不破坏现有记录字段，只允许增加兼容字段：
  - `updatedAt`：最后更新时间。
  - `deletedAt`：软删除时间，用于未来多端同步。
  - `deviceId`：最后修改设备。

## 同步逻辑

第一阶段使用手动/局域网同步接口：

- 手机请求电脑 `/api/sync/state`，获取电脑当前记录版本。
- 手机请求电脑 `/api/sync/pull`，拉取记录、草稿、附件索引。
- 手机向电脑 `/api/sync/push` 推送本地变更。
- 附件通过 `/api/attachments/:entryId/:attachmentId` 继续访问。

冲突处理第一版采用：

- 同一条记录用 `updatedAt` 判断，更新时间新的覆盖旧的。
- 被删除的记录用 `deletedAt` 保留删除痕迹，避免另一端重新同步回来。
- 以后可以升级为冲突列表，由用户手动选择保留哪版。

## Windows 桌面版

第一版不重写前端，复用当前网页功能：

- 桌面软件启动时自动启动本地服务。
- 软件窗口打开 `http://127.0.0.1:8765`。
- 关闭窗口不影响数据。
- 后续可逐步把网页 UI 迁移为真正桌面组件。

## 手机 App

第一版先做手机端工程骨架：

- 可以输入电脑同步地址。
- 可以拉取电脑记录。
- 可以在手机本地保存一份记录缓存。
- 后续再做完整编辑、附件上传和自动发现。

## 迭代顺序

1. 稳住当前网页和数据存储。
2. 增加同步接口。
3. 增加 Windows 桌面壳。
4. 增加手机端骨架。
5. 做手机端完整编辑和附件同步。
6. 做自动发现、冲突处理和安装包。
